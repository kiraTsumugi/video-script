# 05 · 复盘

## 最难的问题

**1. 让"事实可追溯"真正成立，而不是挂个 ID 装样子。**
初稿的脚本内容硬编码，只在字段上挂素材 ID——检索结果实际上没有进入生成逻辑。
评审一眼看穿：素材变了脚本不变，那 cites 就是装饰。修复的关键是**让起草从
`hits.matched_facts` 派生**：旁白逐字取自素材事实，分镜围绕事实生成。
教训：可追溯性不是"字段存在"，而是"内容确实来自那份素材"——要用换素材测试来证明。

**2. 修正循环的状态一致性。**
脚本一改，之前基于旧脚本的估算和检查全部过期。初稿没有作废机制，模型可能拿着
38s 的旧估算决策 28s 的新稿。解法：`revise_script` 后清空旧估算与检查，
强制重新估算、重新检查；`generated` 守卫要求"最后一次检查干净"。**状态机思维：
写操作必须使相关读结果失效。**

**3. 检索匹配的精度权衡。**
2-4 字滑窗召回高但误命中（"支持字母"撞"支持字幕"）；整词匹配精确但召回降
（依赖改写表补召回）。最终选择整词匹配 + 数据驱动的改写表——用"模型观察到 0 命中后
主动改写"的 ReAct 动作弥补召回，而不是让工具偷偷做模糊匹配。工具返回事实，
改写是决策。

## 学习收获

- **可追溯性是内容属性，不是字段属性**：旁白与素材的"逐字关系"才是证据链。
- **写操作使读结果失效**：修正脚本 → 旧检查作废，这条规则消灭了一整类隐蔽 bug。
- **守卫要放在结构层**：prompt 说一百遍"别编造"，不如循环层一句
  "检查不干净不许 generated"。
