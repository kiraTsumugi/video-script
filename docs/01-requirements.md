# 01 · 需求

## 用户与目标

**用户**：短视频创作者/内容运营。
**目标**：在给定主题、受众、平台、目标时长、风格下，生成一份**有事实依据、满足时长限制的
可编辑脚本** —— 标题、分镜、旁白/字幕、预计总时长、素材来源 ID、风险与任务状态。

**非目标**：真实视频渲染、素材上传、发布接入、多语言。

## 范围

| 做 | 不做 |
|---|---|
| 素材检索 / 时长估算 / 规则检查 | 真实渲染/发布 |
| 事实派生起草（旁白取自素材事实） | 向量检索（先用字面匹配+改写表） |
| 超时长修正闭环（压缩→重估） | 毫秒级时长建模 |
| 防编造双层防线 | 界面/部署 |

## 输入

- 主题、受众、平台、目标时长、风格
- 合成产品素材库（`data/materials.json`，每条仅含可引用事实）
- 品牌规则（`data/brand_rules.json`）、改写知识表（`data/synonyms.json`）

## 成功标准（对应考核验收点）

| # | 成功标准 | 判据 |
|---|---|---|
| S1 | 正常生成 | 30s 目标：首稿 38s → 压缩 → 28s，输出分镜+P01 引用+总时长 |
| S2 | 缺关键信息 | 缺主题/时长 → `needs_more_info`，不调工具 |
| S3 | 无素材 | 改写查询后仍无命中 → `no_material`；改写命中则继续生成 |
| S4 | 工具失败 | 重试一次后明确 `tool_error`，不虚报 |
| S5 | 超时长修正 | 压缩+重估闭环；2 轮仍超 → `cannot_satisfy` + 缺口 |
| S6 | 事实可追溯 | 旁白逐字取自素材 facts；逐镜挂 cites；数值/效果核查 |
| S7 | 防编造 | 无依据宣称被规则拦截 + generated 守卫（关键缺陷防线）|
| S8 | ReAct 决策 | 两条路径：38s 超时长（修正）vs 45s 达标（直接检查）|
| S9 | 步数上限 | 超限 `incomplete` |

## 交付结果字段

`标题` / `分镜（画面+旁白+时长+来源ID）` / `预计总时长` / `素材来源 ID` / `风险（违规）` / `任务状态`。
